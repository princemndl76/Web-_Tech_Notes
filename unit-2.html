Unit 2: HTML, JavaScript, CSS and XML

Lists, tables and images

Lists

<ul><li>Unordered item</li></ul>
<ol><li>Ordered item</li></ol>
<dl><dt>Term</dt><dd>Definition</dd></dl>

Tables

<table border="1">
  <tr><th>Name</th><th>Marks</th></tr>
  <tr><td>Asha</td><td>85</td></tr>
</table>

Images: <img src="photo.jpg" alt="Description" width="200">. The alt text is shown if the image fails to load and is read by screen readers.

🎯 Exam Booster

Simple explanation: HTML lists organize items, tables represent structured tabular data, and images add visual content. Semantic HTML improves readability and accessibility.

Example: Use <ul> for a list of topics, <table> for a marks table, and <img> for a diagram with meaningful alt text.

AdvantagesDisadvantages
  • Organizes information clearly
  • Tables are useful for comparisons/data
  • Images improve visual understanding
  • Tables should not be used for page layout
  • Large images can slow pages
  • Missing alt text harms accessibility

Forms and frames

A form collects user input and sends it to a server.

<form action="/submit" method="post">
  <input type="text" name="user" required>
  <input type="password" name="pass">
  <select name="year"><option>3rd</option><option>4th</option></select>
  <textarea name="msg"></textarea>
  <input type="submit" value="Send">
</form>

GET puts data in the URL; POST puts it in the request body.

Frames split a window into separate documents. The <frameset> tag is obsolete; modern pages use <iframe> to embed another page.

🎯 Exam Booster

Simple explanation: HTML forms collect user input using controls such as text fields, radio buttons and submit buttons. Frames/iframes embed another document or browsing context.

Example: A login form sends username and password to a server; an iframe can embed a map or another page.

AdvantagesDisadvantages
  • Forms enable user interaction
  • Validation improves input quality
  • iframes can isolate embedded content
  • Poor form design harms usability
  • Sensitive form data needs secure transport
  • iframes can introduce security and performance concerns

Dynamic HTML with JavaScript

Dynamic HTML (DHTML) combines HTML, CSS and JavaScript so a page can change after it loads, without a refresh.

<p id="msg">Hello</p>
<button onclick="change()">Click</button>
<script>
  function change() {
    document.getElementById("msg").innerHTML = "Changed!";
    document.getElementById("msg").style.color = "red";
  }
</script>

Key ideas: variables (let, const), functions, events (onclick, onsubmit), the DOM, form validation.

🎯 Exam Booster

Simple explanation: Dynamic HTML combines HTML, CSS and JavaScript so a page can change its content, style or behavior without rebuilding the whole document.

Example: JavaScript changes a heading after a button click by updating the DOM.

AdvantagesDisadvantages
  • Interactive interfaces
  • Client-side validation
  • Can update content dynamically
  • Improves user experience
  • JavaScript errors can break interactions
  • Heavy scripts can slow pages
  • Client-side checks alone are not sufficient for security

CSS and Document Type Definition

CSS controls presentation. A rule is selector { property: value; }.

h1 { color: navy; }
.note { background: #ffffcc; padding: 8px; }
#header { border-bottom: 2px solid black; }

Ways to add CSS: inline (style attribute), internal (<style>), external (<link rel="stylesheet">).

DTD defines the legal structure of an XML document: allowed elements, their order and their attributes.

<!DOCTYPE student [
  <!ELEMENT student (name, roll)>
  <!ELEMENT name (#PCDATA)>
  <!ELEMENT roll (#PCDATA)>
]>

🎯 Exam Booster

Simple explanation: CSS controls presentation such as colors, spacing, layout and typography. A DTD defines the permitted structure and elements of an XML document.

Example: CSS can style all h2 headings, while a DTD can specify that an XML document contains a required title element.

AdvantagesDisadvantages
  • CSS separates presentation from content
  • Reusable styles reduce duplication
  • DTD provides structural validation for XML
  • Complex CSS can become difficult to maintain
  • Browser rendering differences may occur
  • DTD has limited datatype support compared with XML Schema

XML and XML schemas

XML (eXtensible Markup Language) stores and transports data using user-defined tags. It must be well-formed: one root element, every tag closed, correct nesting, case-sensitive names.

<?xml version="1.0"?>
<student>
  <name>Asha</name>
  <roll>101</roll>
</student>

XML Schema (XSD) also validates XML but is more powerful than a DTD: it supports data types (xs:integer, xs:date), namespaces and is itself written in XML.

🎯 Exam Booster

Simple explanation: XML is a markup language for representing structured, self-describing data. XML Schema (XSD) defines allowed elements, attributes, structure and datatypes more precisely than DTD.

Example: An XML student record can contain <name>, <rollNo> and <marks>; XSD can require marks to be an integer.

AdvantagesDisadvantages
  • Platform-independent data representation
  • Human-readable structure
  • XSD provides strong validation and datatypes
  • Verbose compared with compact data formats
  • Parsing large XML documents can consume resources
  • Schema design adds complexity

Object models and presenting XML

An object model represents a document as objects a program can access. For XML this is the DOM tree.

Presenting XML:

  • CSS: style XML elements directly, but with no structural change.
  • XSLT: transforms XML into HTML or other formats, using templates and XPath.

🎯 Exam Booster

Simple explanation: An object model represents a document as programmable objects and nodes. XML can be presented by applying CSS or transformations such as XSLT.

Example: A program can access an XML element through a DOM node and then display selected values in a web page.

AdvantagesDisadvantages
  • Programmatic access to document structure
  • Supports transformations and presentation
  • Useful for processing structured data
  • DOM can use significant memory for large documents
  • Transformations add processing complexity

XML processors: DOM and SAX

DOMSAX
ModelTree held in memoryEvent-based stream
MemoryHighLow
AccessRandom, can read and modifyForward only, read only
Best forSmall documents, editingLarge documents, quick scans

SAX fires events such as startElement, characters and endElement as the parser reads the file.

🎯 Exam Booster

Simple explanation: DOM parses an XML document into an in-memory tree. SAX is event-driven and reads the document sequentially without building the complete tree.

Example: Use DOM when random access to many nodes is needed; use SAX for very large XML streams when memory efficiency matters.

AdvantagesDisadvantages
  • DOM: easy navigation and modification
  • SAX: low memory usage and streaming
  • Both support systematic XML processing
  • DOM: higher memory use
  • SAX: more complex event-based programming and no easy random access

CSS selectors and the box model

SelectorExampleMatches
ElementpAll paragraphs
Class.noteElements with class="note"
ID#menuThe element with id="menu"
Descendantdiv pParagraphs inside a div

Box model (from inside out): content, padding, border, margin.

.box {
  width: 200px;
  padding: 10px;
  border: 2px solid black;
  margin: 15px;
}

🎯 Exam Booster

Simple explanation: CSS selectors identify elements to style. The CSS box model describes every element as content surrounded by padding, border and margin.

Example: The selector .card { padding: 20px; border: 1px solid; } styles elements with class card.

AdvantagesDisadvantages
  • Precise reusable styling
  • Responsive layouts are easier to build
  • Box model makes spacing predictable
  • Specificity conflicts can be confusing
  • Different box-model settings can change calculated dimensions

JavaScript form validation

Validation checks input in the browser before it is sent to the server.

<form onsubmit="return check()">
  <input type="text" id="email">
  <input type="submit">
</form>
<script>
function check() {
  var v = document.getElementById("email").value;
  if (v.indexOf("@") === -1) {
    alert("Enter a valid email");
    return false;     // stops submission
  }
  return true;
}
</script>

Client-side validation improves speed and user experience, but the server must validate again because users can bypass the browser.

🎯 Exam Booster

Simple explanation: Form validation checks whether user input satisfies required rules before processing. Client-side validation improves usability, but the server must validate again for security.

Example: Check that an email field is non-empty and contains a reasonable email format before submission.

AdvantagesDisadvantages
  • Immediate feedback
  • Reduces accidental invalid submissions
  • Improves user experience
  • Client-side validation can be bypassed
  • Complex validation logic can increase code size
  • Poor messages can frustrate users

DTD vs XML Schema

DTDXSD
SyntaxNon-XMLXML
Data typesVery limited (#PCDATA)Rich (integer, date, boolean...)
NamespacesNot supportedSupported
Reuse and extensionWeakStrong (complex types)
<xs:element name="roll" type="xs:integer"/>

🎯 Exam Booster

Simple explanation: DTD and XML Schema both define valid XML structure. DTD is older and simpler; XSD is XML-based and provides richer datatype and namespace support.

Example: Use XSD when an application needs typed values such as integer, date or decimal and stronger constraints.

AdvantagesDisadvantages
  • DTD: simple and easy to learn
  • XSD: rich datatypes, namespaces and detailed constraints
  • DTD: limited datatypes and less XML-oriented syntax
  • XSD: more verbose and complex

Quick revision

  • HTML gives structure, CSS gives style, JavaScript gives behaviour.
  • GET shows data in the URL; POST sends it in the body.
  • XML must be well-formed; valid XML also follows a DTD or XSD.
  • XSD beats DTD: XML syntax, data types, namespaces.
  • DOM = whole tree in memory; SAX = event stream, low memory, read-only.
  • XSLT transforms XML into HTML or other formats.

  4. Name the two types of XML parsers.

  3. Explain the rules of a well-formed XML document.
  4. Differentiate DOM and SAX parsers.
  5. Explain the CSS box model.

L3 Apply

  1. Write HTML code to create a registration form with name, email, password, gender (radio) and course (dropdown).
  2. Write a JavaScript function to validate that a password has at least 8 characters.
  3. Write an XML document for a student record and a DTD to validate it.
  4. Write CSS to make all table rows alternate in colour.

L4 Analyze

  1. Compare DTD and XML Schema.
  2. Analyze when to choose SAX over DOM for a 2 GB XML file.
  3. Compare CSS and XSLT for presenting XML.

L5 Evaluate

  1. Justify why server-side validation is still needed even when client-side validation exists.
  2. Assess whether <iframe> is a good replacement for frames.

L6 Create

  1. Design a web page with a navigation list, a marks table and a contact form, styled with an external stylesheet.
