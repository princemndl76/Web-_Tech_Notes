Unit 3: Web services and Ajax

Introduction to web services

A web service is a software component that offers functions over a network using standard protocols, so different platforms and languages can work together.

  • Uses XML or JSON for data and HTTP for transport.
  • Platform and language independent.
  • Types: SOAP-based and RESTful.

🎯 Exam Booster

Simple explanation: A web service is a software service accessible over a network through standardized web technologies. It enables different applications and platforms to communicate.

Example: An online shopping application can call a payment service to verify a transaction.

AdvantagesDisadvantages
  • Platform independence
  • Application interoperability
  • Reusable services
  • Loose coupling
  • Network latency
  • Security and authentication challenges
  • More complex distributed debugging

UDDI and SOAP

UDDI (Universal Description, Discovery and Integration) is a registry where providers publish services and clients find them.

SOAP (Simple Object Access Protocol) is an XML-based messaging protocol. A SOAP message has:

  • Envelope: root element that wraps the message.
  • Header: optional, carries extra information such as authentication.
  • Body: the actual request or response.
  • Fault: optional, reports errors.
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope">
  <soap:Body>
    <getPrice><item>Book</item></getPrice>
  </soap:Body>
</soap:Envelope>

🎯 Exam Booster

Simple explanation: UDDI (Universal Description, Discovery and Integration) was designed as a registry for discovering web services. SOAP is a protocol framework for exchanging structured XML messages.

Example: A SOAP client sends an XML request to a service endpoint and receives an XML response.

AdvantagesDisadvantages
  • SOAP supports formal contracts and extensions
  • UDDI provides a standardized discovery concept
  • Works across platforms
  • SOAP messages can be verbose
  • XML processing adds overhead
  • UDDI is less common in modern public service discovery

WSDL and web service

WSDL (Web Services Description Language) is an XML document that describes a service: what it offers, how to call it and where it lives.

  • types: data types used.
  • message: data exchanged.
  • portType: operations offered.
  • binding: protocol and data format.
  • service: endpoint address.

🎯 Exam Booster

Simple explanation: WSDL (Web Services Description Language) is an XML-based description of a web service, including operations, messages, bindings and endpoints.

Example: A WSDL document can describe an operation named getStudent that accepts an ID and returns student details.

AdvantagesDisadvantages
  • Machine-readable service contract
  • Improves interoperability
  • Helps tools generate client/server code
  • Verbose XML
  • Can be complex to understand manually
  • Strong contracts may reduce flexibility

Architecture of web services

The classic architecture has three roles:

  1. Service provider: creates the service and publishes its WSDL to the registry.
  2. Service registry: UDDI directory where services are listed.
  3. Service requester: finds the service in the registry, then binds to the provider and calls it with SOAP.

The three actions are publish, find and bind.

🎯 Exam Booster

Simple explanation: A common web-service architecture has a service provider, service requester and optional service registry, communicating through network protocols and service descriptions.

Example: A client discovers or already knows a service endpoint, reads its contract and invokes an operation.

AdvantagesDisadvantages
  • Separation of responsibilities
  • Reusable services
  • Interoperability across systems
  • Multiple components increase complexity
  • Network failures must be handled
  • Security must be designed across boundaries

Developing and deploying web services

  1. Write the service logic (for example a Java class).
  2. Expose it as a web service (annotations such as @WebService, or a REST controller).
  3. Generate or write the WSDL.
  4. Deploy to an application server (Tomcat, GlassFish, WildFly).
  5. Publish to a registry, then test with a client or a tool such as SoapUI or Postman.

🎯 Exam Booster

Simple explanation: Development includes designing operations and data, implementing endpoints, testing, securing and deploying the service on a server or cloud platform.

Example: A REST or SOAP service can expose /students/{id}, validate the request, query a database and return structured data.

AdvantagesDisadvantages
  • Reusable backend functionality
  • Easy integration with multiple clients
  • Can be independently deployed and scaled
  • Requires monitoring and versioning
  • Deployment configuration can be complex
  • Backward compatibility must be managed

Ajax

Ajax (Asynchronous JavaScript and XML) updates part of a page by exchanging data with the server in the background, with no full reload.

Benefits: faster response, less bandwidth, smoother user experience.

fetch("/api/notes")
  .then(res => res.json())
  .then(data => {
    document.getElementById("list").textContent = data.length + " notes";
  });

The older approach uses the XMLHttpRequest object with readyState 4 and status 200 meaning success.

🎯 Exam Booster

Simple explanation: AJAX (Asynchronous JavaScript and XML) is a technique in which JavaScript communicates with a server asynchronously and updates part of a page without a full page reload. Modern AJAX commonly uses JSON rather than XML.

Example: A search box sends a request as the user types and updates suggestions without refreshing the page.

AdvantagesDisadvantages
  • Faster-feeling interfaces
  • Partial page updates
  • Reduced full-page reloads
  • More client-side complexity
  • Requires careful error/loading handling
  • Search-engine and accessibility behavior must be considered

CORBA

CORBA (Common Object Request Broker Architecture) lets objects written in different languages on different machines call each other.

  • IDL: Interface Definition Language describes object interfaces.
  • ORB: Object Request Broker carries requests and replies.
  • IIOP: protocol used between ORBs over TCP/IP.
  • Stub and skeleton: proxy code on the client and server sides.

🎯 Exam Booster

Simple explanation: CORBA (Common Object Request Broker Architecture) is a distributed-object standard that allows objects written in different languages and running on different systems to communicate through an Object Request Broker.

Example: A client can invoke a method on a remote object without needing to know its physical location.

AdvantagesDisadvantages
  • Language and platform interoperability
  • Supports distributed objects
  • Hides many communication details
  • Complex architecture
  • Heavy compared with many modern HTTP APIs
  • Less common in modern web development

SOAP vs REST

Best forEnterprise, strict contractsWeb and mobile apps

REST uses URLs for resources and HTTP methods for actions: GET /students/5 reads student 5, DELETE /students/5 removes them.

🎯 Exam Booster

Simple explanation: SOAP is a protocol-based messaging approach with XML envelopes and formal standards. REST is an architectural style that commonly uses HTTP resources and representations such as JSON.

Example: A banking enterprise system may use SOAP for a strict contract, while a public web API may use REST with JSON.

AdvantagesDisadvantages
  • SOAP: strong contracts, standards and enterprise extensions
  • REST: simple, cache-friendly and widely used for HTTP APIs
  • SOAP: verbose and heavier
  • REST: conventions can vary and formal contracts are not inherent

WSDL structure example

<definitions name="PriceService">
  <message name="GetPriceRequest"><part name="item" type="xs:string"/></message>
  <message name="GetPriceResponse"><part name="price" type="xs:float"/></message>

  <portType name="PricePort">
    <operation name="getPrice">
      <input message="GetPriceRequest"/>
      <output message="GetPriceResponse"/>
    </operation>
  </portType>

  <binding name="PriceBinding" type="PricePort"> ... </binding>
  <service name="PriceService"> ... </service>
</definitions>

🎯 Exam Booster

Simple explanation: A WSDL document typically describes types, messages, port types/interfaces, bindings and service endpoints. Together these parts define how a client can call the service.

Example: The types section defines an XML schema; messages reference those types; bindings specify the communication style; service defines the endpoint.

AdvantagesDisadvantages
  • Clear machine-readable contract
  • Supports tool-assisted integration
  • XML verbosity
  • Large WSDL files can be difficult to maintain

Quick revision

  • Web service = platform-independent function call over a network.
  • SOAP = XML messaging (Envelope, Header, Body, Fault). WSDL describes. UDDI lists.
  • Publish, find, bind: the three actions of the architecture.
  • REST is lightweight and uses HTTP methods; SOAP is heavier but has a strict contract.
  • Ajax updates part of a page without a reload (XMLHttpRequest or fetch).
  • CORBA = IDL + ORB + IIOP for cross-language distributed objects.
