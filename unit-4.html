Unit 4: Web 2.0 and the semantic web

Web 2.0: interactive and social web

Web 2.0 turned the web from read-only pages into a platform where users create and share content.

  • Blogs: dated posts, newest first.
  • Wikis: pages anyone can edit (Wikipedia).
  • Social networking sites: profiles, connections and sharing (Facebook, LinkedIn).

🎯 Exam Booster

Simple explanation: Web 2.0 describes the shift from mostly static publishing toward interactive, user-participatory and socially connected web applications.

Example: A social platform allows users to create posts, comment, react and share content.

AdvantagesDisadvantages
  • User participation
  • Rich interaction
  • Collaborative content creation
  • Community building
  • Privacy concerns
  • Misinformation and abuse
  • Platform dependence and moderation challenges

Technologies behind Web 2.0

  • AJAX: partial page updates.
  • RSS: XML feed format that delivers new content to subscribers.
  • Ruby on Rails: full-stack framework built on convention over configuration and the MVC pattern.

🎯 Exam Booster

Simple explanation: Web 2.0 commonly relies on AJAX, JavaScript, APIs, RSS/Atom, server-side frameworks and asynchronous communication to create responsive applications.

Example: An AJAX request retrieves new notifications while the rest of the page remains visible.

AdvantagesDisadvantages
  • Responsive interfaces
  • Component reuse through APIs
  • Continuous content updates
  • More client-side complexity
  • Compatibility and security concerns
  • Higher dependency on network services

Open APIs and Web 3.0 (semantic web)

Open API: a public interface that lets developers use a service's data or features.

Semantic web (Web 3.0): data is given machine-readable meaning, so software can understand and connect it. It relies on RDF, ontologies and URIs.

🎯 Exam Booster

Simple explanation: Open APIs expose functionality or data for other applications. The Semantic Web aims to represent information with machine-understandable meaning so software can discover relationships and reason over data.

Example: An application calls a public weather API; semantic metadata can describe that a location is a city and has a population value.

AdvantagesDisadvantages
  • Integration and reuse
  • Machine-readable relationships
  • Supports data interoperability
  • API misuse and rate limits
  • Semantic data modeling is complex
  • Privacy and data-quality issues

Widgets, mashups and RDF

  • Widget: small embeddable component such as a weather box or a map.
  • Mashup: a page that combines data from several sources, for example restaurants plotted on a map.
  • RDF: Resource Description Framework describes data as subject - predicate - object triples.

🎯 Exam Booster

Simple explanation: Widgets are small reusable interface components. Mashups combine data or services from multiple sources. RDF (Resource Description Framework) represents information as subject-predicate-object triples.

Example: A dashboard combines a map API, weather data and local event information.

AdvantagesDisadvantages
  • Rapid composition of applications
  • Reusable components
  • Combines multiple information sources
  • Dependency on external services
  • API changes can break mashups
  • Data consistency and security can be difficult

Web-based information systems and search engines

A web-based information system collects, stores and delivers information through a browser.

Search engine pipeline:

  1. Crawling: bots follow links to find pages.
  2. Indexing: page content is stored in a searchable index.
  3. Ranking: results are ordered by relevance and quality signals (PageRank is one example).

🎯 Exam Booster

Simple explanation: A web-based information system stores, processes and presents information through web interfaces. Search engines crawl/index content and rank results for user queries.

Example: A college portal lets students search notes, while a search engine indexes public pages and returns ranked matches.

AdvantagesDisadvantages
  • Centralized online access
  • Search makes large information collections usable
  • Accessible from many devices
  • Search ranking can be imperfect
  • Privacy and tracking concerns
  • Systems depend on availability and data quality

Recommender systems and benefits of blockchain

Recommender systems suggest items a user may like.

  • Collaborative filtering: uses the behaviour of similar users.
  • Content-based filtering: uses item features.
  • Hybrid: combines both.

Blockchain benefits: decentralisation, transparency, tamper resistance and traceability.

🎯 Exam Booster

Simple explanation: Recommender systems suggest items based on user behavior, content or similarity. Blockchain is a distributed ledger that records transactions in linked blocks using cryptographic techniques.

Example: A learning site recommends notes based on topics previously viewed; blockchain can record verifiable transactions between participants.

AdvantagesDisadvantages
  • Personalization can improve discovery
  • Blockchain can provide shared tamper-evident records
  • Decentralized systems can reduce dependence on one authority
  • Recommendations can create filter bubbles
  • Blockchain systems may have scalability/energy costs depending on design
  • Bad input data can still produce bad outcomes

Edge computing and dark mode

Edge computing processes data close to the user (CDN nodes, edge functions) to cut latency and bandwidth use.

Dark mode offers a dark colour scheme that reduces eye strain in low light and can save battery on OLED screens.

@media (prefers-color-scheme: dark) {
  body { background: #121212; color: #eee; }
}

🎯 Exam Booster

Simple explanation: Edge computing processes data closer to users/devices instead of sending everything to a distant central cloud. Dark mode uses a dark color scheme to reduce visual brightness and can improve comfort for some users.

Example: An IoT camera can process events locally at the edge and send only important results to the cloud.

AdvantagesDisadvantages
  • Lower latency
  • Reduced bandwidth for some workloads
  • Can improve responsiveness
  • More distributed infrastructure to manage
  • Limited resources at edge locations
  • Dark mode is not automatically better for every user or display

Web 2.0 features and RSS example

  • User-generated content: users create the content.
  • Rich interaction: Ajax-based pages.
  • Participation: comments, ratings, tags, sharing.
  • Web as a platform: services and APIs, not just pages.

An RSS feed is an XML file that lists recent items:

<rss version="2.0">
  <channel>
    <title>College News</title>
    <link>https://example.com</link>
    <item>
      <title>Exam schedule out</title>
      <link>https://example.com/exam</link>
    </item>
  </channel>
</rss>

🎯 Exam Booster

Simple explanation: RSS (Really Simple Syndication) provides machine-readable feeds of updated content so users or applications can follow changes without manually checking every site.

Example: A news reader fetches an RSS feed and displays newly published articles.

AdvantagesDisadvantages
  • Automatic content updates
  • Simple machine-readable format
  • Useful for aggregation
  • Not all sites publish feeds
  • Feeds may provide limited content
  • Users can receive too many updates

Blog vs wiki vs social network

BlogWikiSocial network
AuthorOne or fewMany, collaborativeEvery user
OrderNewest firstBy topicFeed or timeline
EditingOwner editsAnyone can editOwn posts only
ExampleWordPressWikipediaLinkedIn

🎯 Exam Booster

Simple explanation: A blog usually presents posts in chronological order, a wiki is collaborative and continuously edited, and a social network focuses on profiles, relationships and user interaction.

Example: A personal technology blog publishes articles; a wiki maintains shared documentation; a social network connects users and their posts.

AdvantagesDisadvantages
  • Blogs: strong publishing model
  • Wikis: collaboration and shared knowledge
  • Social networks: communication and community
  • Blogs can be one-way
  • Wikis need editorial control
  • Social networks raise privacy and moderation concerns

Quick revision

  • Web 2.0 = participation: blogs, wikis, social networks.
  • Technologies: Ajax, RSS, Ruby on Rails (MVC, convention over configuration).
  • Semantic web uses RDF triples (subject, predicate, object).
  • Mashup = combining data from several sources into one page.
  • Search engine = crawl, index, rank.
  • Recommenders: collaborative, content-based, hybrid.
